Modelo de CMS

Painel pro cliente editar o site.

Entregue um admin de verdade: o cliente troca textos, posts e fotos sem te chamar. Aqui está o passo a passo completo, do zero até o painel no ar, pra você copiar, adaptar e cobrar.

Um CMS por cliente

  • Cada cliente ganha a própria pasta no seu projeto (não mistura tudo num painel só).
  • Na Vercel, sobe um deploy por cliente, apontando pra pasta dele.
  • Assim você entrega com organização e, se quiser, depois separa o código daquele cliente.
clients/
  padaria-da-rua/     ← CMS do cliente 1
  clinica-sorriso/    ← CMS do cliente 2
configs/
  padaria-da-rua.config.ts
  clinica-sorriso.config.ts

Com dados reais do cliente, deixe o projeto privado e nunca versione senhas ou chaves.

Na entrega

Passo a passo

Siga na ordem. Se travar, desça até os erros mais comuns.

Instale Node e pnpm

Baixe o Node.js LTS. Depois, no terminal:

npm i -g pnpm
node -v
pnpm -v

Se os dois comandos mostrarem um número de versão, está ok.

Copie o template pro seu GitHub

Abra o template no botão acima, clique em Fork e copie a URL do seu projeto (Code → HTTPS).

Baixe pro PC e instale

git clone https://github.com/SEU-USUARIO/criador-de-cms-builders.git
cd criador-de-cms-builders
pnpm install

A primeira instalação demora. Espere terminar sem erro vermelho.

Crie o config do primeiro cliente

cp templates/config-examples/demo-corp.config.ts configs/meu-cliente.config.ts

Abra o arquivo e mude pelo menos o slug (só minúsculas, números e hífen) e o displayName. Depois valide:

pnpm cms-factory validate --config configs/meu-cliente.config.ts

Gere a pasta do CMS no seu PC

pnpm cms-factory create-client --config configs/meu-cliente.config.ts --skip-provision

O --skip-provision evita criar coisas na nuvem agora. Só gera a pasta clients/<slug>/.

Crie um projeto no Supabase

Em supabase.com, crie um projeto. Em Settings → API e → Database, copie a URL, a chave anon, a service_role e as duas connection strings (pooler na porta 6543 e direto na 5432).

Preencha o .env.local

cd clients/meu-cliente
cp .env.example .env.local

Cole as chaves nos campos certos (há comentários no arquivo). Nunca faça commit desse arquivo.

Se não achar o .env.example, copie de templates/client-app/.env.example.

Suba o banco, o admin e rode local

Troque meu-cliente pelo seu slug:

pnpm --filter meu-cliente run db:migrate
pnpm --filter meu-cliente run seed:locales
pnpm --filter meu-cliente run seed:admin -- voce@email.com 'SenhaForte123!'
pnpm --filter meu-cliente run dev

Abra http://localhost:3010, faça login e complete o MFA no celular. Crie um post de teste pra confirmar.

O migrate também trava o banco (segurança). Não pule esse passo.

Repita pra o próximo cliente

Outro slug, outra pasta, outro projeto no Supabase. Mesmo fluxo do config em diante.

Publique na Vercel (na hora de entregar)

Importe o seu projeto na Vercel. Root Directory: clients/<slug>. Cole as mesmas variáveis do .env.local e faça o deploy. Um cliente = um projeto na Vercel.

Deu erro? Os mais comuns

pnpm: command not found

O pnpm não instalou. Rode de novo npm i -g pnpm e feche/abra o terminal.

validate falhou

Leia a mensagem: costuma ser typo no slug ou campo inválido no config. Corrija e rode o validate de novo.

migrate / conexão com o banco

Confira DATABASE_URL e DIRECT_URL (senha, project-ref, sslmode). No Supabase, libere o IP se pedir.

Login / MFA / idioma errado

Rode seed:locales e o seed:admin de novo. No primeiro login o MFA (app autenticador) é obrigatório.

Ainda travou? Manda um print do erro no grupo. A gente destrava rápido.
